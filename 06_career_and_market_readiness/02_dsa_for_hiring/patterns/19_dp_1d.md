Dynamic programming (DP) solves a problem by combining answers to overlapping subproblems, each computed once. Every DP answer in an interview has the same five parts, and saying them aloud before coding is most of the score:

1. **State:** what `dp[i]` means, in one sentence ("the fewest coins that make amount i").
2. **Recurrence:** how `dp[i]` follows from smaller states.
3. **Base cases.**
4. **Order:** which states must be computed first.
5. **Answer:** which state (or the best over several) is returned.

In one-dimensional DP the state is a single index: a prefix of the input, an amount, or a position.

## Recognise it

| When you see… | Think… |
|---|---|
| "number of ways to…", "minimum/maximum cost to reach…" | DP over positions or amounts |
| choices at each element that affect only the next one or two | `dp[i]` from `dp[i-1]`, `dp[i-2]`; roll into two variables |
| "can the string be split into dictionary words" | `dp[i]` = prefix of length i is splittable |
| "longest increasing subsequence" | O(n²) DP, then O(n log n) with patience sorting |
| products with negative numbers | track both the max and the min ending here |
| buy/sell with cooldowns or fees | a small state machine per day (holding, sold, resting) |
| a greedy idea that you cannot prove | try DP; compare both on small inputs |

## Core templates

**Rolling variables (House Robber).** State: best loot from the first i houses. Only the last two states are needed.

```python
from bisect import bisect_left
from functools import lru_cache


def rob(nums):
    prev2 = prev1 = 0                  # best for houses[:i-2], houses[:i-1]
    for x in nums:
        prev2, prev1 = prev1, max(prev1, prev2 + x)
    return prev1


def rob_circular(nums):                # House Robber II: first and last are adjacent
    if len(nums) == 1:
        return nums[0]
    return max(rob(nums[1:]), rob(nums[:-1]))
```

**Unbounded choices over an amount (Coin Change).** State: fewest coins for amount a.

```python
def coin_change(coins, amount):
    INF = amount + 1                   # more coins than could ever be needed
    dp = [0] + [INF] * amount
    for a in range(1, amount + 1):
        for c in coins:
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1
    return dp[amount] if dp[amount] != INF else -1
```

**Prefix DP with a validity check (Decode Ways).** A single digit is a letter only if it is not `0`; two digits only if they form 10–26.

```python
def num_decodings(s):
    prev2, prev1 = 1, 1 if s and s[0] != "0" else 0    # dp[0], dp[1]
    for i in range(2, len(s) + 1):
        cur = prev1 if s[i - 1] != "0" else 0
        if 10 <= int(s[i - 2:i]) <= 26:
            cur += prev2
        prev2, prev1 = prev1, cur
    return prev1 if s else 0
```

**Split into words (Word Break).** State: `dp[i]` is True when `s[:i]` can be split.

```python
def word_break(s, words):
    words = set(words)
    max_len = max(map(len, words), default=0)
    dp = [True] + [False] * len(s)
    for i in range(1, len(s) + 1):
        for j in range(max(0, i - max_len), i):
            if dp[j] and s[j:i] in words:
                dp[i] = True
                break
    return dp[len(s)]
```

**Longest increasing subsequence in O(n log n).** `tails[k]` is the smallest possible tail of an increasing subsequence of length k + 1; it stays sorted, so each element is placed with binary search.

```python
def length_of_lis(nums):
    tails = []
    for x in nums:
        i = bisect_left(tails, x)      # bisect_left: strictly increasing
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)
```

**Track max and min (Maximum Product Subarray).** A negative number turns the smallest product into the largest.

```python
def max_product(nums):
    best = hi = lo = nums[0]
    for x in nums[1:]:
        candidates = (x, hi * x, lo * x)
        hi, lo = max(candidates), min(candidates)
        best = max(best, hi)
    return best
```

**State machine (Best Time to Buy and Sell Stock with Cooldown).** Three states per day: holding a share, just sold, resting with no share.

```python
def max_profit_cooldown(prices):
    hold, sold, rest = float("-inf"), 0, 0
    for p in prices:
        hold, sold, rest = max(hold, rest - p), hold + p, max(rest, sold)
    return max(sold, rest)
```

**Expand around centres (palindromic substrings).** Not a table, but the standard O(n²) answer with O(1) space.

```python
def count_substrings(s):
    total = 0
    for centre in range(2 * len(s) - 1):
        l, r = centre // 2, centre // 2 + centre % 2
        while l >= 0 and r < len(s) and s[l] == s[r]:
            total += 1
            l -= 1
            r += 1
    return total
```

**Top-down with memoisation.** Often the fastest way to a correct recurrence; convert to bottom-up if depth is large.

```python
def climb_stairs_memo(n):
    @lru_cache(maxsize=None)
    def ways(i):
        if i <= 1:
            return 1
        return ways(i - 1) + ways(i - 2)
    return ways(n)
```

**Java.**

```java
static int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);
    dp[0] = 0;
    for (int a = 1; a <= amount; a++)
        for (int c : coins)
            if (c <= a) dp[a] = Math.min(dp[a], dp[a - c] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
}

static int lengthOfLIS(int[] nums) {
    int[] tails = new int[nums.length];
    int size = 0;
    for (int x : nums) {
        int lo = 0, hi = size;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (tails[mid] < x) lo = mid + 1; else hi = mid;
        }
        tails[lo] = x;
        if (lo == size) size++;
    }
    return size;
}
```

## Complexity

Time = number of states × work per state. House Robber: n states × O(1). Coin Change: amount × number of coins. Word Break: n × max word length substring checks, each O(max word length) to hash. LIS: O(n²) with the basic DP, O(n log n) with `tails`. Space is the table size, often reducible to O(1) when the recurrence looks back a fixed distance.

## Common bugs

1. An incomplete state: the future depends on something the state does not record (for example, whether the previous day was a sale).
2. Wrong base case: `dp[0] = 1` (one way to make 0) vs `dp[0] = 0` (zero coins to make 0) depends on what dp counts.
3. Decode Ways: treating `"0"` as a letter or `"06"` as 6 (exercise 1).
4. Deep top-down recursion: amount 10⁴ with coin 1 means 10⁴ nested calls (exercise 2).
5. Using `bisect_right` in LIS, which computes the longest *non-decreasing* subsequence.
6. Rolling variables updated in the wrong order (use tuple assignment).

## AI-era exercises

**Exercise 1 · Find the bug.**

```python
def num_decodings_ai(s):
    dp = [0] * (len(s) + 1)
    dp[0] = 1
    for i in range(1, len(s) + 1):
        dp[i] = dp[i - 1]
        if i >= 2 and 10 <= int(s[i - 2:i]) <= 26:
            dp[i] += dp[i - 2]
    return dp[len(s)]
```

It passes `"12"` and `"226"`. Find the shortest failing input, and a two-character input where it double counts.

<details><summary>Answer</summary>

`"0"` returns 1 instead of 0: the code treats every single digit as a letter, including `0`. `"10"` returns 2 instead of 1: it counts "1, 0" (invalid) as well as "10". Fix: add `dp[i - 1]` only when `s[i - 1] != "0"`. A brute force that tries every split into pieces of length 1 or 2 and checks each piece against 1..26 finds both in a fraction of a second on all strings of length ≤ 5 over the digits 0–3.
</details>

**Exercise 2 · A hidden limit.** An assistant writes Coin Change top-down:

```python
from functools import lru_cache


def coin_change_ai(coins, amount):
    @lru_cache(maxsize=None)
    def best(a):
        if a == 0:
            return 0
        if a < 0:
            return float("inf")
        return min(best(a - c) + 1 for c in coins)
    r = best(amount)
    return -1 if r == float("inf") else r
```

The recurrence is right. LeetCode's constraints allow `amount` up to 10⁴. What happens locally with `coins = [1], amount = 5000`, and how do you fix it without changing the recurrence?

<details><summary>Answer</summary>

It raises `RecursionError`: with coin 1 the call chain `best(5000) → best(4999) → …` is 5,000 frames deep, and CPython's default limit is 1,000 frames. Fixes: compute bottom-up (the template), which has no recursion; or warm the cache in increasing order (`for a in range(amount + 1): best(a)`) so each call recurses only one level. Raising `sys.setrecursionlimit` is fragile because the C stack can still overflow. Always check the maximum recursion depth against the constraints when an assistant hands you a memoised solution.
</details>
